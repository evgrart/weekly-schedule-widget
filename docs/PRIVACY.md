# Privacy and publishing

This repository contains source code and fictional examples only. No account,
personal calendar URL, assignment snapshot, browser session, cookie, token or
personal screenshot is included. Commit authors use a GitHub noreply address.

Runtime files live in `%LOCALAPPDATA%\WeeklyScheduleWidgetPublic`, not in this
checkout. They may include:

- `config.json`: the user's private calendar URL and window preferences;
- `cache-*.ics`: private calendar content;
- `shad-deadlines.json`: private assignment names, URLs and deadlines;
- `shad-browser-profile`: authenticated browser state;
- synchronization status and local diagnostics.

Do not upload or share that directory. A private iCal URL is a credential: anyone
who has it may be able to read the calendar. If exposed, reset the secret address
in Google Calendar and update the local settings. Do not paste cookies or tokens
into issues. For an authentication issue, report the error category, not account
data or browser-profile files.

The app connects to the configured Google Calendar feed and SHAD/Yandex during
sign-in and assignment checks. It does not send calendar data to GitHub or to a
project-specific backend. Yandex/SHAD pages may load their own normal site resources.

Examples and the README screenshot are generated by `demo.py`, which uses a
disposable data directory and fictional 2030 events. It does not load the real
configuration or sign in. Tests also use a temporary data directory and mock all
network-dependent GUI refreshes.

Before publishing changes, run:

```powershell
.\.venv\Scripts\python.exe tools/check_secrets.py
.\.venv\Scripts\python.exe tools/check_secrets.py --history
```

The checker reports file names and categories, never matched secret values. It is
a backstop, not a guarantee; inspect changed files and images as well. A normal
`.gitignore` does not remove a secret from existing Git history.
